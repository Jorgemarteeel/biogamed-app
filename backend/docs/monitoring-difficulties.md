# Frequent recorded errors — first delivery

## Scope and contract

Global, staff-only analysis linked from `/seguimiento`; no course ownership, enrolment or groups are invented. Student requests are rejected by `require_content_staff`, both in the API and before the UI fetch. `GET /monitoring/difficulties` accepts the same `start`, `end` (inclusive civil days in Atlantic/Canary) and `game=ALL|TRIVIAL|PASAPALABRA`, plus `minimum` (default 5, integer 1–100000), `skip` (>=0) and `limit` (1–100, default 20). Dates filter shared match creation or standalone session creation, never answer time. Invalid date/order/game/minimum/page bounds are rejected. No reconciliation, writes or migrations. CSV export is documented below.

Response: platform scope, timezone, evaluated observations, excluded deduplicated records, matching group total and one page of groups. Each group exposes question ID, opaque historical reference Q<question>/C<first matching answer-copy ID>, game/format and readable label, historical text, evaluated/account/correct/wrong counts and error percentage. Never names, emails, individual submissions, solutions, option arrays, acceptance alternatives or private snapshots. UI reuses MonitoringFilters/DayPicker/Radix selection and preserves applied filters, minimum and page in the URL. Minimum is part of the pending form; editing never queries until Consultar. It is an operational threshold, not statistical validity. There is no restriction to questions with errors; zero-error groups remain visible.

## Units, deduplication and identity

The observation is one evaluated stored response per registered participant session and question. AnswerLog has a unique (game_session_id, question_id) constraint. Trivial submission rejects duplicate question IDs and completed resubmission (services/game.py); shared command replay is idempotent and only evaluation creates an AnswerLog (services/pasapalabra.py). Passes and unresolved questions create no evaluated log. Guest local participants have no account/session logs; shared sessions additionally must match the participant's user and match IDs. Thus both online accounts contribute separate observations but the local guest is never attributed to the host.

A defensive SQL row_number picks the latest answered_at, then greatest log ID, within session/question before validation and aggregation. Current engines do not support several educational final logs for the same pair; the unique constraint rejects them. If reading a legacy database permitting duplicates, the last saved evaluation is the deterministic final observation, not an additional attempt. Commands, network retries and MatchQuestion pass states are not queried or summed. Missing logs are never invented as failures.

Historical identity uses the answer-copy fields, not today's Question: question ID + game + saved format + exact copied text + type + options (including their order) + letter + correct option + exact word + accepted alternatives. PostgreSQL JSON keys are canonicalized via JSONB/text for grouping; array order remains significant. SQLite fixtures use JSON text with canonical fixture ordering. Different IDs, formats or content/correction versions cannot merge; same text alone is not an identity. The C reference is the first stored matching answer copy, not an editorial revision counter. No fingerprint derived from solutions is exposed. The original bank is never joined, so retired questions remain included and edits cannot replace old text. No formal revision ID exists; identical evaluated content can group even across metadata-only edits. Topic/category/difficulty were not all recorded on AnswerLog, are not reconstructed, and are not displayed as historical classifications here. Alternative ordering changes may conservatively split otherwise equivalent content.

Minimum complete evidence: nonempty copied text, mode/type consistency and a known stored boolean result; Trivial also needs a nonempty options array, valid selected/correct indices and a boolean consistent with those indices. Pasapalabra requires a saved text response (empty is a real evaluated response) and nonempty copied exact word. A missing accepted-alternatives list does not mean the correction was unknown. Incomplete/incoherent final copies are counted as excluded, once per session/question, not silently labelled wrong. Older sessions without start snapshots can contribute if their AnswerLog holds this complete evaluated copy; otherwise they are excluded. Sessions/questions that have no log at all are not a quantifiable excluded response and are never inferred. Excluded guests are outside the registered population entirely.

Evaluated = correct + wrong. Error percentage = 100 * wrong/evaluated. Accounts = distinct saved registered user IDs within that group. Formats are separate; results are recorded error frequencies, not a learning, causal or academically validated difficulty measure. Order is error fraction descending, observations descending, question ID, format, then first copy ID for stable ties.

## SQL and performance limits

Database-side joins, window deduplication, validation, grouping/count-distinct, sorting and offset/limit; only the requested aggregate page and scalar totals reach the server response/browser. No Python materialization of all question texts/answer rows. Private grouping columns remain in SQL and never enter the DTO. Scalar counts and grouping can scan all matching answer logs; the existing schema has session/question keys but no index for the full historical grouping expression. Several aggregate statements may repeat that work. Default 20 rows, at most 100, bounds transfer size, not database work. Date ranges should be narrowed for large installations; no load/concurrency benchmark or query-plan tuning is claimed. No index migration was justified by measured load in this delivery. Concurrent new legitimate answers can change totals between aggregate queries or pages; no long snapshot transaction is held.
